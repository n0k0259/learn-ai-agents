An agent can only act on the information available to it, and designing and managing that information is called **context engineering**. Context is everything the model actually "sees" on a call: the conversation history, the developer's system instructions, the tool descriptions and other information. In Harness terms, context engineering is a core implementation of the "Context and Tools" layer: it decides what the agent sees at each decision point and how that information is structured. The through-line is explicit information management — the API message structure defines the skeleton, a stable prefix raises the KV Cache hit rate, prompts, Skills and the status bar carry rules, on-demand knowledge and current state, and compression raises the information density of history while preserving decisions, constraints, failures and sources.
